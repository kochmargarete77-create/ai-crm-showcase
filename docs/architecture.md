# 公开架构说明

本项目只展示交互层，但页面背后的设计遵循以下通用原则。

## 1. AI 不是事实来源

AI 可以提取材料、生成摘要、标记缺项并形成草稿。正式订单、订阅、金额、退款和账户余额必须经过授权人员确认，并由服务端事务写入。

## 2. 草稿和正式台账隔离

未确认草稿不计入成交额、利润、回款、到期数量和经营报表。识别失败时保留原始材料与手工录入能力，不让模型可用性阻塞业务。

## 3. 同步交易与异步任务分层

查询、编辑和正式确认适合走同步事务；多文件解析、OCR、通知和定时检查适合进入队列。异步任务应具有请求号、幂等键、重试次数、心跳和明确的终态。

## 4. 财务记录只追加不覆写

充值、扣费、退款和调整应形成独立流水。错账通过冲正原流水并新增正确流水处理，保留操作者、原因和时间。

## 5. 多端共享同一业务边界

电脑、手机、聊天机器人和批量导入最终调用同一套服务端权限与校验规则。渠道只改变交互方式，不改变业务授权。

## 6. 敏感信息单独保护

密码、2FA、Cookie、Token 和原始材料不应进入普通日志、搜索索引、通知或模型上下文。生产系统需使用专门的加密、访问审计和密钥轮换方案。

## 公开范围

本仓库没有实现上述后端能力，仅用虚构数据展示它们在前端应呈现的状态和交互。这样既能说明产品与工程思路，也不会公开商业系统的核心实现。
